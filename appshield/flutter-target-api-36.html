Flutter: fix targetSdk 36 for the Google Play deadline

Google requires most apps and updates to target API level 36 (Android 16) starting August 31, 2026, with extensions available to November 1, 2026 through Play Console. In a Flutter project this is a two-line gradle edit, then a rebuild.

Pattern 1: hardcoded targetSdk in android/app/build.gradle

Older Flutter project templates set the SDK versions directly as numbers. Open android/app/build.gradle (or build.gradle.kts if your project uses Kotlin DSL) and find the android {} block:

android {
    compileSdkVersion 36
    defaultConfig {
        targetSdkVersion 36
        minSdkVersion 21
    }
}

In Kotlin DSL (build.gradle.kts) the same edit looks like:

android {
    compileSdk = 36
    defaultConfig {
        targetSdk = 36
    }
}

Pattern 2: newer templates using flutter.targetSdkVersion

Current Flutter project templates reference the SDK version from the Flutter tool itself instead of hardcoding a number:

android {
    compileSdk = flutter.compileSdkVersion
    defaultConfig {
        targetSdk = flutter.targetSdkVersion
    }
}

With this pattern, the number comes from the Flutter SDK you have installed, not from your project file. Run flutter upgrade to pull a Flutter/Android embedding version whose default targetSdkVersion is 36, then confirm with flutter doctor -v. If your installed Flutter SDK is too old to default to 36, either upgrade Flutter or fall back to Pattern 1 and hardcode compileSdk = 36 / targetSdk = 36 directly, overriding the flutter.* reference.

Rebuild and retest

  1. Clean the build cache. Run flutter clean so no stale gradle outputs linger with the old SDK number.
  2. Build the release app bundle. Run flutter build appbundle. This produces the .aab file Play Console expects, now compiled against and targeting API 36.
  3. Retest on an Android 16 device or emulator. Behavior changes tied to targeting API 36 (permission handling, edge-to-edge display, background restrictions) only appear at runtime on Android 16, not at compile time. Test your core flows there before uploading.
  4. Upload the new bundle to Play Console. Confirm the Play Console listing now shows target API level 36 for the release.
